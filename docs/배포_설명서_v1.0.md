# 공공데이터 렌즈 — MCP 서비스 배포 설명서 v1.0

- 대상: `docker-compose.prod.yml` (MCP 배포 스택 A — gateway + mcp + api + 코어 웹)
- 독자: 별도 서버(클라우드 VM 등)에 본 서비스를 설치·운영하는 관리자
- 생성형 컨시어지(스택 B, `docker-compose.concierge.yml`)는 **본 문서 범위가 아니며** 별도 서비스로 배포한다
  (분리 근거: 설계서 §2·§11, [부속명세](부속명세_v1.0.md) "배포 표면 분리" 조항)

---

## 1. 무엇을 배포하는가

| 컨테이너 | 역할 | 노출 |
|---|---|---|
| `gateway` | 리버스 프록시 — 유일한 진입점, 레이트 리밋·익명 접근 로그 | 호스트 `${GATEWAY_PORT}` (기본 8088) |
| `mcp` | 원격 MCP 서버(streamable HTTP, 무상태) | gateway 내부 전용 |
| `api` | 정본 URI 해소(§7) + 코어 웹용 REST(비생성형 GET 전용) | gateway 내부 전용 |
| `web` | 코어 웹 SPA(검색·비교·변경 피드·활용 사례) — 컨시어지 없는 빌드 | gateway 내부 전용 |

**공개 표면 전체 목록** (`/api`·`/projects` 밖의 알 수 없는 경로는 SPA가 `index.html`을 반환한다 — 404가 아니라 웹 화면):

```
/                      코어 웹(SPA)
/projects/public-data-lens/mcp   원격 MCP 엔드포인트 (커스텀 커넥터 등록 URL — /mcp 별칭 없음)
/projects/public-data-lens/**   §7 정본 URI (dataset/{목록키}, catalog/current, context·rules·shapes·spec·prompts, 벌크 파일)
/api/**                코어 웹용 REST — GET 전용, /api/concierge* 는 404
/privacy               개인정보·로그 고지 (= /api/resources/privacy)
/healthz               LB 헬스체크용
```

**LLM API 키가 필요 없다.** 이 스택은 전부 비생성형·읽기 전용이다.

## 2. 요구 사항

### 서버
- Linux x86_64 또는 arm64, **Docker Engine 24+ / Compose v2**
- 권장 최소 사양: 2 vCPU / 4 GB RAM / 20 GB 디스크
  (카탈로그 DB ~0.6 GB/릴리스 + 벌크 산출물, 릴리스는 월 1개씩 누적)
- 단일 인스턴스 전제 — rate limit·캡이 프로세스 메모리 기반이므로 **api·mcp 복제 수는 1을 유지**한다.
  수평 확장이 필요해지면 게이트웨이 계층 제한으로 이전해야 한다(차기 백로그).

### 네트워크·도메인
- **TLS는 상위 LB/프록시에서 종단**한다. Claude 등 호스트 앱의 커스텀 커넥터는 **https 필수**.
- **도메인은 정본 네임스페이스와 일치해야 한다**: JSON-LD `@id`가 전부
  `https://service.datahub.kr/projects/public-data-lens/...`이므로, 서비스 도메인이 `service.datahub.kr`가
  아니면 정본 URI가 해소되지 않는다(§7 Cool URIs). 다른 도메인을 쓰려면 코드의
  `BASE_URI`(apps/server/datanav/config.py)를 바꾸고 **카탈로그를 재빌드**해야 하며,
  이는 식별자 체계 변경(설계서 재개봉 사유)임을 인지할 것.

### 원본 데이터
- 공공데이터포털 **「공공데이터활용지원센터_공공데이터포털 목록개방현황」** 월간 CSV
  (data.go.kr에서 배포). 이 파일 하나가 유일한 입력이다.

## 3. 설치 (최초 1회)

```bash
# 1) 코드
git clone <저장소 URL> && cd <저장소 디렉터리>

# 2) 환경변수
cp .env.example .env
vi .env
```

> ZIP으로 전달해야 하면 수동 압축 대신 `git archive -o release.zip HEAD`를 쓴다 —
> `.env.example` 같은 dotfile이 포함되고 `node_modules`·캐시·OS 부산물은 제외된다.

`.env` 필수 항목 — **아래 두 필수 변수는 미지정 시 스택이 기동하지 않는다**(조용한 fail-open 방지):

| 변수 | 값 | 설명 |
|---|---|---|
| `GATEWAY_BIND` | 기본 `127.0.0.1` | 게이트웨이 바인딩 주소 — 기본 루프백으로 원 서버 직접 접근(TLS 우회)을 차단. LB가 다른 호스트면 이 호스트의 내부 IP로 지정 |
| `GATEWAY_PORT` | 예: `8088` | LB가 전달할 호스트 포트 |
| `GATEWAY_REAL_IP_FROM` | **[필수]** LB 내부 대역 CIDR, 쉼표로 다중 지정 — 예: `10.0.0.0/8,100.64.0.0/10` | 미지정 시 기동 실패. 잘못 지정하면 모든 사용자가 LB IP 하나로 묶여 IP당 제한이 서비스 전체 한도가 된다. 직접 노출(LB 없음)이면 `127.0.0.1`(no-op)을 명시 |
| `DATANAV_MCP_ALLOWED_HOSTS` | **[필수]** 예: `service.datahub.kr` | 미지정 시 기동 실패. Host 헤더 검증(DNS 리바인딩 보호) |

```bash

# 4) 카탈로그 첫 빌드 (스택 기동 전에 필요 — api healthcheck가 미빌드를 unhealthy로 판정)
```

```python
import asyncio, json
from mcp.client.streamable_http import streamablehttp_client
from mcp import ClientSession

async def main():
    async with streamablehttp_client("https://<도메인>/projects/public-data-lens/mcp") as (r, w, _):
        async with ClientSession(r, w) as s:
            await s.initialize()
            print([t.name for t in (await s.list_tools()).tools])
            res = await s.call_tool("get_context", {})
            print(json.loads(res.content[0].text)["data"]["currentSnapshot"])

asyncio.run(main())
```

## 4. LB / TLS 구성 요점

- LB(또는 전단 nginx/Caddy)가 443 TLS를 종단하고 `GATEWAY_PORT`로 평문 전달한다.
  게이트웨이는 기본 `127.0.0.1` 바인딩이므로 LB가 다른 호스트면 `GATEWAY_BIND`를 내부 IP로 지정한다.
- LB는 실제 클라이언트 IP를 `X-Forwarded-For`에 **추가(append)**해야 하며, 그 LB의 내부 대역(들)을
  `GATEWAY_REAL_IP_FROM`에 쉼표로 지정해야 gateway가 실제 클라이언트 IP를 복원한다(IP당 rate limit의 전제).
  AWS ALB·CloudFront·Cloudflare처럼 다중 대역에서 접근하는 LB는 해당 대역을 모두 나열한다.
- MCP 응답은 단일 JSON(`json_response=True`)이라 LB 버퍼링 설정과 무관하다.
  (SSE 스트리밍 모드로 되돌리면 LB에도 gateway처럼 버퍼링 해제·300초 타임아웃이 필요하다.)
- 헬스체크 경로: `/healthz` (액세스 로그 미기록).

## 5. 운영

### 월간 카탈로그 갱신 (매월 1회)

```bash
COMPOSE_FILE=docker-compose.prod.yml scripts/monthly_update.sh <새 목록개방현황.csv> <YYYY-MM>
```

빌드→수용검사→원자적 포인터 교체→api·mcp 재기동→12개월 초과 사용 로그 정리→배포 확인까지
한 번에 수행한다. 검증 실패 시 기존 릴리스가 그대로 서비스된다(무중단).
같은 스냅샷을 재빌드하면 직전 릴리스의 변경 이력(diff)이 자동 승계된다.

### 데이터 구조 관측 스토어 배포·갱신 (S1~S2 기능)

구조 관측(원본 컬럼·예시값)은 **로컬에서 적재하고 산출물만 서버로 전송**한다 —
스크리닝 전 원본(프로파일 CSV)은 서버에 올리지 않는다(관측 설계 v2.2 §7).

```bash
# 관리 PC에서(최초 1회): 가상환경 준비
python3 -m venv .venv && .venv/bin/pip install -e apps/server

# 관리 PC에서: 프로파일 CSV 적재(검증→안전 스크리닝→라이선스 게이트)
cd apps/server && ../../.venv/bin/python scripts/ingest_profile.py <프로파일_컬럼별.csv> <관측시점Z>

# 산출물만 서버로 전송 후 재기동
rsync -av data/observations/observations.db <서버>:<설치경로>/data/observations/
ssh <서버> 'cd <설치경로> && docker compose -f docker-compose.prod.yml restart api mcp'

# 확인
curl -s https://<도메인>/api/status | grep structureCoverage
```

- 스토어가 없으면 구조 표면은 전 레코드 `NOT_COLLECTED`로 동작한다(오류 아님) —
  구조 기능 없이도 서비스는 완전하다.
- **예시값 공개는 기본 비활성**(`DATANAV_EXAMPLES_PUBLIC=0`) — 발췌 제공 범위의 법적
  확인(S0-2) 후 compose 환경변수로 개방한다. 개방 전에도 컬럼명·관측 유형·고유값수는 제공된다.

### 로그 (§10 이행)
- **게이트웨이 접근 로그**: 원 IP·쿼리 문자열(검색어)을 기록하지 않는 익명 형식
  (`메서드 경로 상태 크기 처리시간`). 옵트아웃 헤더 요청은 접근 로그에서도 제외.
  컨테이너 로그는 10MB×5로 로테이션.
- **앱 사용 로그**: `data/logs/usage-일자.jsonl` — 난수 ID/IP의 HMAC만(원 IP 미저장·역산 불가,
  키는 `DATANAV_ANON_HMAC_KEY`), DNT/GPC/`X-Datanav-No-Log` 요청은 전면 미기록.
  보존 12개월 — api 컨테이너가 하루 한 번 스스로 삭제한다(월간 빌드 성패와 무관).
- 고지 전문은 `/privacy`로 공개된다.

### 백업
- 필수: `data/catalog/releases/` + `data/catalog/current.json` (서비스 정본)
- 필수(구조 관측 기능 사용 시): `data/observations/observations.db` — 코드로 재생성 불가,
  관리 PC의 프로파일 CSV에서만 재적재 가능
- 권장: `data/raw/` (원본 스냅샷 — 이것만 있으면 카탈로그는 코드로 전체 재빌드 가능)
- 제외 가능: `data/logs/` (지표 원천이 필요하면 포함)

### 업그레이드

```bash
git pull
docker compose -f docker-compose.prod.yml up -d --build   # 재빌드 후 교체
```

- 웹은 캐시 정책(index.html no-cache)이 있어 사용자 브라우저에 즉시 반영된다.
- 공개 계약(Tool 스키마)은 semver로 관리된다: minor는 무중단 적용 가능,
  breaking(major)은 재승인·공지 없이 배포하지 않는다(부속 명세 참조).

### 릴리스 정리
릴리스 디렉터리는 자동 삭제되지 않는다. 디스크가 부담되면 오래된
`data/catalog/releases/<릴리스>`를 수동 삭제하되, **current.json이 가리키는 릴리스와
직전 릴리스(diff 승계용)는 남긴다.**

## 6. 보안 모델 요약

- 인증 없음·읽기 전용·전 표면 GET(웹 REST)·무상태 MCP — 쓰기 경로 자체가 없다.
- 레이트 리밋: gateway에서 IP당 MCP 2 req/s(버스트 20), 일반 5 req/s. 앱 계층 120 req/min 병행.
- MCP Host 헤더 검증(`DATANAV_MCP_ALLOWED_HOSTS`) — DNS 리바인딩 방지.
- 원천 텍스트(목록 제목·설명)는 비신뢰 입력 — Tool 설명과 모든 응답에 주입 방어 고지 포함.
- api·mcp 컨테이너는 `read_only: true`로 루트FS 쓰기를 봉쇄(쓰기는 데이터 볼륨·tmpfs `/tmp`만,
  mcp의 데이터 마운트는 읽기 전용). web·gateway(nginx)는 캐시·설정 생성 경로가 필요해 제외 —
  단 앱 동작상 쓰기는 없다.

## 7. 문제 해결

| 증상 | 원인·조치 |
|---|---|
| api가 unhealthy | 카탈로그 미빌드. §3의 3) 첫 빌드부터 수행 |
| `docker compose restart` 실패(첫 설치) | 컨테이너 미생성 상태. `up -d`를 먼저 |
| 포트 충돌(`address already in use`) | `.env`의 `GATEWAY_PORT` 변경 |
| 기동 실패 — `GATEWAY_REAL_IP_FROM`/`DATANAV_MCP_ALLOWED_HOSTS` 오류 메시지 | 필수 env 미지정(의도된 fail-closed). §3 표 참조 |
| 모든 요청 429 | `GATEWAY_REAL_IP_FROM`이 실제 LB 대역과 불일치해 전 사용자가 LB IP로 묶임. LB 대역을 쉼표로 모두 나열 |
| api가 데이터 볼륨 쓰기 실패(Permission denied) | `chown -R 10001:10001 data` 미수행(비루트 컨테이너) |
| MCP 접속이 400/차단 | `DATANAV_MCP_ALLOWED_HOSTS`와 실제 도메인 불일치 |
| 웹이 옛 화면 | 강력 새로고침. 서버측은 index.html no-cache라 재발 시 LB 캐시 설정 확인 |
| 검색 0건 과다 | AND→OR 완화가 warnings에 표기됨 — 정상 동작. 골든셋 평가는 `scripts/eval_goldenset.py` |
| 빌드 실패 | 수용검사(§11) 로그 확인 — 원본-정규화 행수 불일치, 목록키 중복 등. 기존 서비스는 영향 없음 |

## 9. 환경변수 레퍼런스 (prod 스택)

| 변수 | 기본 | 설명 |
|---|---|---|
| `GATEWAY_BIND` | 127.0.0.1 | 게이트웨이 바인딩 주소(루프백 기본 — TLS 우회 차단) |
| `GATEWAY_PORT` | 8088 | 게이트웨이 노출 포트 |
| `GATEWAY_REAL_IP_FROM` | **필수(기본 없음 — 미지정 시 기동 실패)** | 신뢰 LB 대역 CIDR, 쉼표 구분 다중 가능 |
| `DATANAV_MCP_ALLOWED_HOSTS` | **필수(기본 없음 — 미지정 시 기동 실패)** | Host 헤더 검증 도메인(쉼표 구분) |
| `DATANAV_CORS_ORIGINS` | (없음=차단) | 교차 출처 허용 도메인 — 동일 출처 웹만 쓰면 불필요 |
| `DATANAV_RATE_LIMIT_PER_MIN` | 120 | 앱 계층 IP당 분당 한도 |
| `DATANAV_USAGE_LOG` / `DATANAV_LOG_DIR` | 1 / data/logs | 사용 로그 스위치·경로 |
| `DATANAV_SHACL_SAMPLE` | 500 | 빌드 시 SHACL 표본 수(0=전수) |
| `DATANAV_EXAMPLES_PUBLIC` | 0 | 1이면 관측 예시값을 응답에 노출(S0-2 확인 후) — api·mcp 양쪽 전달 |
| `DATANAV_ANON_HMAC_KEY` | (없음=데이터 볼륨에 자동 생성·영속) | 익명 식별자 HMAC 비밀키 — 캡·지표 연속성은 기본 보장, 다중 인스턴스 공유 시 지정 |

컨시어지 관련 변수는 이 스택에서 무효(`DATANAV_CONCIERGE_ENABLED=0` 고정)다.
