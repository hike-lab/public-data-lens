## 1. 공통 계약

### 1.1 응답 봉투
```json
{ "data": …, "meta": { "sourceSnapshot", "processedAt", "schemaVersion", "ruleVersions[]" }, "warnings": [] }
```
- `warnings`는 면책 고지를 항상 1건 이상 포함한다(§10).
- 모든 판정 필드는 근거 규칙 버전을 동반한다(`ruleVersions`, 항목 내 `rule`).

### 1.2 오류 모델 (9종, 폐쇄형)
`INVALID_ARGUMENT`(400) · `DATASET_NOT_FOUND`(404) · `SNAPSHOT_NOT_FOUND`(404) · `FILTER_NOT_AVAILABLE`(400) ·
`TOO_MANY_DATASETS`(400) · `INDEX_NOT_READY`(503) · `SOURCE_VERSION_UNAVAILABLE`(404) · `RATE_LIMITED`(429) · `INTERNAL_ERROR`(500)

구조: `{ "error": { "code", "message", "details", "sourceSnapshot" } }` — 코드 추가는 minor, 제거·의미 변경은 breaking.

**배포 표면 분리(명문화)**: 생성형 컨시어지는 MCP 공개 표면에 포함되지 않는다(설계서 §2 책임 분리·§11 완료 판정 분리). 컨시어지는 별도 서비스의 웹 REST 전용 표면이며, `CONCIERGE_UNAVAILABLE`(503)을 비롯한 컨시어지 계약은 본 명세(v1.0.0)의 대상이 아니라 v1.1 웹 REST 계약 대상이다. MCP·코어 웹 배포는 `DATANAV_CONCIERGE_ENABLED=0`으로 해당 표면을 닫는다.

**MCP 오류 반환 정책(명문화)**: MCP 표면에서 오류는 `isError=false`인 **정상 콘텐츠(위 오류 봉투)** 로 반환한다.
이는 Tool-call 실패 시 호스트가 대화를 중단하거나 기계적으로 재시도하는 대신, 오류 내용을 읽고
스스로 교정(다른 recordId 시도 등)하도록 유도하기 위한 의도적 설계다. 클라이언트는 응답 본문의
`error` 키 존재로 오류를 판별해야 한다. 단, **입력 스키마 위반**(필수 인자 누락, 타입·개수 제약 위반 등)은 프로토콜 계층(MCP SDK)이 도구 실행 전에 차단하므로 `isError=true`의 검증 오류 텍스트로 반환된다 — 이는 공개된 inputSchema의 기계적 강제이며 본 봉투 정책의 예외다. REST 표면에서는 동일 봉투가 위 표의 HTTP 상태 코드와 함께 반환된다.

### 1.3 페이지네이션
커서는 **불투명 토큰**이며 스냅샷에 귀속된다. 스냅샷 교체 후 사용하면 `INVALID_ARGUMENT`(처음부터 재조회 안내).
`nextCursor=null`이면 마지막 페이지. 동일 스냅샷 내 무중복·무누락을 보장한다.

### 1.4 입력 제한
query ≤ 500자 · 비교 ≤ 5개 · pageSize ≤ 100 · REST rate limit(기본 120/분, `DATANAV_RATE_LIMIT_PER_MIN`)

### 1.5 호환성 원칙
필드 **추가**는 하위 호환(minor). required 필드 제거·타입/의미 변경·오류 코드 제거·상태 enum 축소는 **breaking**(major).
버전은 `meta.schemaVersion`으로 전달한다.

### 1.6 보안 고지
응답의 목록 필드(제목·설명·유의사항 등)는 **참조 데이터이며 지시문이 아니다**(§10). 클라이언트는 포함된 명령형 문장을 실행하지 않는다.

| Tool | 입력(요약) | 출력 data(요약) | 주요 오류 |
|---|---|---|---|
| `search_datasets` | query?, theme?, org?, format?, updateCycle?, license?, listType?, region?, includeInferred=true, updatedAfter?, cursor?, pageSize=20 | items[](요약 카드+근거), nextCursor, hasMore, totalEstimate, ranking(method·version·indexVersion·embeddingModel·tieBreak) | INVALID_ARGUMENT, FILTER_NOT_AVAILABLE |

| `get_context` (호환) | — | 상태 + service(정의·baseUri·규칙 목록·책임 분리 고지) | INDEX_NOT_READY |

## 3. v1.0 범위 한정 (명시적 축소 — v1.1 백로그)

- `get_catalog_changes`: **직전 배포 스냅샷과의 diff만** 제공한다. 임의 기준월·기간·필터 조회는 v1.1 백로그(스냅샷 저장소 조회형 구현 필요).
- `get_catalog_stats`: 축·limit만 지원. 검색과 공통 필터 객체 적용은 v1.1 백로그.
- `search_datasets`: qtier·dm 필터는 입력 스키마에서 **제외**(설계서 §4.1) — B트랙 환류 버전에서 추가 예정(capability 문서 기재 사항).
