# ADR-017: 이슈 #1(실사용 보고) 반영 — 사유 코드와 사람용 문안의 분리, 전송 계층 원인 판정

- 상태: 채택
- 날짜: 2026-08-21
- 관련: ADR-016(스냅샷 수용 게이트·diff-v1.1), ADR-006(v1.6 additive — `baseUnavailableReason` 신설)
- 계기: [Issue #1](https://github.com/hike-lab/public-data-lens/issues/1) — 외부 이용자의 16개 시·도 49,060건 전수 수집 후기

## 맥락

외부 이용자가 약 460요청으로 49,060건을 전수 수집하고 결과를 지역 언론 데이터 기사에
활용한 뒤 문제 2건·제안 2건을 보고했다. `totalEstimate`와 `get_catalog_stats` org축
버킷이 전 구간 일치했다는 확인은 자체적으로 재현하기 어려운 규모의 외부 검증이다.

보고된 4건 중 본 ADR이 다루는 것은 2건이다(나머지는 아래 "다른 경로" 참조).

**문제 1 — `get_catalog_changes`가 빈 결과.** 공개 서버에 스냅샷이 하나뿐이라 diff가
없다. 응답은 `baseUnavailableReason: "FIRST_SNAPSHOT_OR_DIFF_NOT_GENERATED"`로
사유를 정직하게 알리고 있었으나, **'왜 비었는지'만 알리고 '언제 되는지'를 알리지 않았다.**
소개 문구의 대표 질문("지난달 공공데이터 목록에서 사라진 데이터가 있어?")이 작동하지
않는 상태와 겹쳐 초기 이용자가 고장으로 오인했다.

**문제 2 — 비UTF-8 요청 본문에 generic 오류.** MCP SDK의 POST 핸들러
(`mcp/server/streamable_http.py:648`)가 catch-all로 받아 `-32603 "Error handling POST
request"`만 반환한다. 제보자는 한글 질의만 실패하는 것처럼 보여 서버 버그로 오인했고,
원인 규명에 시간을 썼다. 클라이언트 잘못이지만, **원인을 알 수 없는 오류는 디버깅
비용을 이용자에게 전가한다.**

## 결정

**1. 사유 코드와 사람용 문안을 분리해 둘 다 제공한다.** `baseUnavailableReason`은
기계용 분기값으로 유지하고, `warnings[]`에 해소 시점을 명시한다.

```
비교 기준 이전 스냅샷이 없습니다 — 첫 스냅샷이거나 diff 미생성 상태입니다.
월간 스냅샷이 2회 이상 축적되면 다음 회차 빌드부터 변경 이력이 생성됩니다.
```

`warnings[]`가 이 문안의 정본이다(불변식 4 — 프론트엔드는 원문을 치환하지 않는다).
호스트 LLM도 이 문안을 그대로 읽는다.

**2. 전송 계층에서 인코딩 원인을 먼저 판정한다** (`datanav/api/asgi_guard.py`).
POST 본문의 UTF-8 디코딩 가능성만 검사하는 순수 ASGI 미들웨어를 SDK 앱 앞단에 둔다.

- **JSON-RPC 코드는 `-32700`(Parse error)**. 해석 불가한 입력은 규격상 Parse error이며
  내부 오류(`-32603`)가 아니다. SDK의 분류가 부정확했다.
- 계약 오류 모델(§4.3)의 `INVALID_ARGUMENT`를 `error.data.code`에 병기해 REST 표면과
  코드를 맞춘다. **오류 코드 9종은 그대로다 — 신설하지 않는다.**
- 실패 바이트 위치·사유를 `details`에 담는다. 제보자가 겪은 "한글만 실패하는 것처럼
  보이는" 상황에서 CP949 등 다른 인코딩임을 바로 알 수 있다.
- ASCII만 있는 본문은 CP949로 보냈어도 UTF-8로 유효하므로 막지 않는다(거짓 양성 방지).

**3. `BaseHTTPMiddleware`를 쓰지 않는다.** SSE·스트리밍 응답을 깨뜨린다. 순수 ASGI로
구현하고, 판정 후 소비한 ASGI 메시지를 그대로 재생해 하위 앱이 본문을 다시 읽게 한다.
본문 버퍼링에는 1 MiB 상한을 둔다(MCP 요청 본문은 작다).

**4. HTTP 기동 경로를 자체 구성으로 바꾼다.** `mcp.run(transport="streamable-http")`는
앱을 내부에서 조립해 미들웨어를 끼울 수 없다. `FastMCP.run_streamable_http_async`와
같은 기동을 `_run_streamable_http()`로 복제하고 앞단에 미들웨어를 둔다. stdio 모드는
영향받지 않는다. 배포 커맨드(`python -m datanav.api.mcp_server --http`)가 이 경로를 탄다.

## 계약 영향

`SCHEMA_VERSION`을 올리지 않는다. `warnings[]`는 자유 문자열 배열이고, 새 오류 코드를
만들지 않았으며, 미들웨어는 전송 계층이라 Tool 스키마에 닿지 않는다.

### 기관 유형 분류를 분리한 근거 (Issue #9)

`제공기관코드` 접두 2자리가 계층과 상당히 대응한다(`10~18`·`97` 중앙, `30~59` 기초,
`61~65` 광역, `70~93` 교육청, `B######` 공공기관 510개·목록 31.6%). 규칙으로 굳히면
틀린다 — **본청과 소속기관이 같은 접두를 공유하는 구간이 62개 중 26개**다.

```
6300000  대전광역시              6300309  대전광역시 상수도사업본부
5690000  세종특별자치시(광역)      5540000  경기도 광주시(기초)
1320000  경찰청                 1810001  경찰청 서울특별시경찰청
```

정확도 높은 휴리스틱은 가능하지만 정확한 분류는 불가능하다. 유형이 틀리면 "이 지자체는
개방이 부진하다" 같은 분석이 조용히 틀린다. 재현되어야 하는 판정은 결정론적으로 수행하며
근거 없는 추정을 계약 필드로 노출하지 않는다(설계서 §2).

부수 관측 — 2026-07 스냅샷에는 `광주광역시`·`전라남도` 본청 목록이 0건이고
`전남광주통합특별시`(`6130000`, 1,262건)가 있다. 행정구역 통합이 반영된 것으로 보인다.
**기관 식별 자체가 시점에 따라 변하므로, 유형 분류는 시점을 가진 분류여야 한다.**
이슈 #1의 "광주광역시 검색" 문제도 이와 연결된다.

## 배포 시 주의

PR #7이 README에 추가하는 "현재 첫 스냅샷 축적 단계" 표기는 2026-07 배포 시점에
거짓이 된다. PR #7 본문도 이를 명시하고 있다. 머지 순서와 무관하게 **배포 전 제거**해야
한다. 본 ADR의 `warnings[]` 문안은 최초 빌드 상황에서만 발화하므로 그대로 유지된다.

## 기각한 대안

- **새 오류 코드 `INVALID_ENCODING` 신설** — 오류 코드 9종은 계약 표면이고, 인코딩
  오류는 `INVALID_ARGUMENT`의 부분집합이다. `details`로 충분히 구별된다.
- **SDK 패치·몽키패치** — 상류 코드를 손대면 SDK 업그레이드마다 깨진다.
- **README만 고친다(문제 1)** — 문서를 읽지 않고 Tool을 호출하는 호스트 LLM에는
  닿지 않는다. 응답 자체가 스스로를 설명해야 한다.
