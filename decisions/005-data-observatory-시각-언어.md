# ADR-005: Data Observatory 시각 언어 — 팔레트 전환·폰트 조달·홈 서사

- 상태: 채택 (STEP 9)
- 날짜: 2026-08-04

## 맥락

외부 UI/UX 검토(2026-08-04)가 코어 표면의 라이트 블루 시스템이 "행정 시스템 또는
범용 AI SaaS"로 읽힌다고 지적했다. 검토안의 다수(행 컴포넌트·근거 표기·렌즈·상태색
규칙·웹/MCP 역할)는 STEP 4~8에서 이미 구현돼 있었고, 남은 실질은 ① 시각 언어의
고유화 ② 미결이던 폰트 조달 ③ 홈의 서사화·목적 진입점이었다. Readiness/Relations
렌즈·'추천' 명명·프론트 적합성 문장·컬럼명 해석 컬럼은 계약(qualityTier null 고정,
sourceName 무변형)과 충돌하여 기각했다.

## 결정

1. **팔레트(코어 표면 1층 토큰만 교체)**: 액센트 = deep teal `#0c6b70`(hover `#095458`,
   워시 `#e6f1f1`), 캔버스 = 따뜻한 백색 `#faf9f7`, 텍스트 = 먹색 네이비 `#151c28`,
   구조선 = 차가운 회청색(`#dee3e8`/`#ccd5dc`/`#b9c4cd`), 한계 = 황갈 `#b45309` 유지,
   근거 녹색·상태 의미 토큰 불변. 상태 태그 모서리 999px→6px. 그림자는 기존의 최소
   수준 유지. **2층(의미)·3층(컴포넌트) 무변경** — STEP 2의 토큰 분리가 이 전환을
   1블록 교체로 만들었다(설계 목적 실증).
2. **폰트 조달 = npm 셀프호스팅**: `pretendard` 가변 동적 서브셋(한글+라틴 — 라틴은
   Inter 파생이므로 Inter 별도 조달 불필요) + `@fontsource/ibm-plex-mono`(400·600).
   CDN 배제 근거: 외부 요청 없는 자기완결 배포·오프라인 재현성. 모노스페이스는
   `code/pre/kbd/samp` 전역 — 기계가 정한 문자열에만 쓰는 경계는 마크업(`<code>`)이
   담당한다.
3. **히어로 카피**: 건수 중심("96,056건을 근거와 함께") → 가치 중심("찾는 것에서
   이해하고 활용하는 것으로"). 건수는 보조 문장으로 강등.
4. **목적 진입점**: 검색바 3모드(키워드/컬럼/**목적**). 목적 모드는 POST /api/plan을
   호출하고 상세의 '활용 초안' 렌즈와 같은 렌더러(PlanResult)를 쓴다 — 표시 로직
   단일 지점.
5. **홈 서사 2블록 추가**(가이드 §3 완주): 탐색 서사(실제 /api/plan 응답의 축약 —
   목적 해석→후보→역할·근거→한계, 날조 없음) + Dataset anatomy(구조 관측 레코드
   1건 해부 — 원본 컬럼명 무변형).
6. **ConnectView**: 설치 안내보다 capability demonstration 우선(자연어→Tool 단계→
   근거 있는 응답 3단). 응답 예시는 결과 날조 없이 계약 필드 이름으로만 구성.
   '추천'이 아니라 '후보'.

## 기각한 대안과 이유

- **Inter 별도 조달**: Pretendard 라틴이 Inter 파생이라 중복. 용량만 는다.
- **CDN 폰트**: 외부 요청 발생 — 로그 고지·자기완결 배포 원칙과 상충.
- **Readiness/Relations 렌즈, 프론트 적합성 문장, 컬럼 해석 컬럼**: 서버 근거 없음.
  DESIGN.md §5 "만들지 않는 렌즈"·§8 언어 규칙과 충돌.
- **블루 유지 + 명도 조정**: 검토 지적의 핵심(행정 시스템 연상)이 해소되지 않음.

## 영향

- 코어 표면 시각 베이스라인 전면 갱신(팔레트·서체가 모든 화면에 반영).
- 번들에 폰트 자산 추가(동적 서브셋 — 초기 로드는 사용 글리프 범위만).
- 컨시어지(그린) 표면은 1층 분리 덕에 무변경.
