# ADR-003: URL 라우팅 채택 — 의존성 없는 pushState 라우터

- 상태: 채택 (STEP 7)
- 날짜: 2026-08-04

## 맥락

App.jsx의 `useState('search')` 단일 문자열이 뷰 전환의 전부여서 공유·북마크·뒤로가기가
불가능했고, 비교 뷰에 다녀오면 검색 상태가 소실됐다. nginx.conf의 `try_files`(와 vite
preview의 SPA 폴백)는 이미 딥링크에 대응하고 있어 서버 변경은 불필요했다.

## 결정

react-router 등 외부 의존성을 추가하지 않고 `src/router.js`(≈40줄)의
pushState 라우터를 쓴다. URL을 뷰 상태의 단일 진실로 삼는다:

- 뷰: `/`(검색) · `/compare` · `/changes` · `/about` · `/connect` · `/concierge`
- 데이터셋 상세: `/datasets/{recordId}?lens=overview|structure|evidence`
  — 새 탭에 붙여넣으면 그 데이터셋이 열린다(밑판은 직전 뷰, 직접 진입 시 검색)
- 검색 상태: `/?q=…&listType=&region=&updateCycle=&format=&inferred=0`
  또는 `/?mode=columns&cols=위도,경도` — `replaceState`로 반영(히스토리 오염 방지)

닫기: 앱 내부에서 열었으면 `history.back()`(이전 화면 복귀), 직접 진입이면 검색으로.
다른 뷰에 다녀온 뒤의 검색 복원은 마지막 검색 URL 재적용 + 마운트 시 URL 파싱으로 한다.

## 근거

- 필요한 것은 경로 6개 + 상세 1개 + 쿼리 직렬화뿐이다. react-router 도입은 공개
  릴리스 직전에 번들·감사 표면을 늘리는 비용 대비 이득이 없다.
- URL 복원 로직(어떤 파라미터가 검색을 재실행하는가)은 계약이 아니라 표현이므로
  프론트에 있어도 불변식(백엔드 로직 복제 금지)을 건드리지 않는다.

## 영향

- 검색·상세가 공유 가능한 URL이 됐다. Escape/뒤로가기가 상세를 닫는다.
- SearchView는 마운트 시 URL에서 상태를 복원한다 — 비교 뷰 왕복 시 소실 문제 해소.
- 한계: 커서 페이징 위치(더 보기 횟수)는 URL에 담지 않는다(무한 스크롤 성격).
