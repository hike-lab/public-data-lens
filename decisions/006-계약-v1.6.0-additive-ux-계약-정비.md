# ADR-006: 계약 v1.6.0 + UX 계약 정비(P0 게이팅·사용자 언어)

- 상태: 채택 (STEP 10)
- 날짜: 2026-08-04

## 맥락

2차 외부 UX 검토(2026-08-04)의 P0 지적 — "목적 검색·활용 초안이 HTTP 404",
"localhost MCP 주소" — 는 구버전 서버(v1.4 이하)에 신버전 프론트를 붙인 버전 스큐
관측이었다. 그러나 **스큐를 방어하지 않은 것 자체가 결함**이다: 프론트는 서버보다
먼저 배포될 수 있다. 나머지 지적(내부 용어 노출·검색 근거 부재·규칙명 노출)은
사용자 언어 문제로 수용했다.

## 결정 — P0 방어

1. **기능 게이팅**: `supportsPlan(status)` — `/api/status`의 `meta.schemaVersion ≥ 1.5.0`
   일 때만 목적 탭·활용 초안 렌즈·탐색 서사 블록을 노출. 딥링크는 시도를 허용하고
   오류 문안으로 강등한다(진입점 숨김 ≠ 기능 차단).
2. **오류 모델**: HTTP 상태 코드 원문("HTTP 404")을 사용자에게 노출하지 않는다.
   서버 오류 봉투가 없으면 404→"서버가 아직 제공하지 않는 기능" 문안, 기타→재시도 안내.
3. **MCP 주소 = 정본 상수**: `window.location.origin` 파생을 폐기하고
   `https://service.datahub.kr/projects/public-data-lens/mcp`(§7 영구 불변)를 하드코딩.
   dev·프리뷰에서 로컬 주소가 복사되는 문제 제거.

## 결정 — 계약 v1.6.0 (additive)

1. **`summaryItem.matchedFields[]`** — query 있을 때 검색어 토큰이 나타난 필드
   (title/keywords/description/orgName). "왜 이 결과인가"를 서버 사실로 표시
   (프론트 재추정 금지). 포함 판정 기준이라 FTS 완화 일치와 다를 수 있음을 스펙에 명시.
2. **`get_catalog_changes`: `summary{status: n}` + `baseUnavailableReason`** —
   변경량 한눈 요약과 기준 부재 사유 코드(문자열 결합 판별 제거, §12 잔여분).
3. **`search sort=relevance|modified`** — 질의로 거르되 최신 수정순 정렬 선택.
   `ranking.basis`가 실제 순서를 반영.
4. **`summaryItem.rowCountListed` 방출 교정** — 스펙에는 있었으나 검색 응답이
   실제로는 방출하지 않던 필드(스펙-코드 불일치 발견분).

동반: SCHEMA_VERSION/SPEC_VERSION 1.6.0, gen_tool_spec 재생성(라이브 검증), 130 passed.

## 사용자 언어 정비(P1)

- `구조 확인됨`→`컬럼 구조 확인됨`(+"값 품질 보증 아님" 툴팁), `기재 13/16`→
  `메타데이터 13/16 항목`. 표시 라벨은 우리 소유(서버 경고 문안 치환 금지와 무관).
- 규칙 버전 원문은 근거 렌즈의 접힘("판정 방식")으로 이동 — L1에는 판정 스냅샷만.
- 원본 보기 버튼을 상세 상단 고정(재배포하지 않는 서비스의 핵심 행동).
- 긴 기관 원문 설명은 접기(요약을 생성하지는 않는다 — §8), 키워드에 '원문' 출처 표기.
- 정렬·검색 기준은 ranking.basis(계약 필드)로 표시 — 문자열 추론 부활 아님.
- MCP 등록 안내 카드 3열 → 아코디언, 연결 확인 단계 추가. 내비 'AI에 연결'→'MCP 연결',
  focus ring 단일 체계.

## 기각 유지 (2차 검토안 중)

컬럼 '추정 의미' 열, 프론트 생성 요약·활용 문장, confidence 자연어 등급화 —
전부 서버 근거 없는 판정 신설(§7 위반). 근거는 ADR-005와 동일.
