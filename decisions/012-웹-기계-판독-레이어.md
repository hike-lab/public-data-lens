# ADR-012: 웹 표면 기계 판독 레이어 — meta·JSON-LD·정적 본문·llms.txt

- 상태: 채택
- 날짜: 2026-08-08
- 관련: ADR-005(시각 언어 — index.html 책임 목록), ADR-009(공개 저장소·대표 표면),
  구현 가이드 Phase 1(`index.html`에 `meta description`·`og:*`·`canonical`·`color-scheme` 등재 —
  본 ADR 전까지 미이행)

## 맥락

2026-08-08 라이브 표면 점검에서 대표 페이지(`service.datahub.kr/projects/public-data-lens/`)가
순수 CSR 셸로 확인됐다.

- JS를 실행하지 않는 소비자가 읽을 본문 텍스트 0자
- `meta description`·`og:*`·`canonical`·JSON-LD 전무
- `/llms.txt` 404

AI-Ready Data 실증 프로젝트의 대표 페이지가 기계 판독 불가라는 자기모순이며,
제품 약속(무엇이 존재하고 무엇이 한계인지)을 사람에게만 말하고 기계에는 말하지
않는 상태였다. 필요한 실시간 수치(스냅샷·지연·구조 커버리지)는 `/api/status`가
이미 제공하고 있었다.

## 결정

1. **`index.html`에 정적 기계 판독 레이어를 둔다.**
   - `meta description`·`og:*`·`canonical`·`color-scheme` — canonical은 정본
     네임스페이스(§7) 절대 URL로 하드코딩한다(정본은 배포 후 변경 불가이므로 상수가 맞다,
     ConnectView의 `MCP_URL` 전례).
   - schema.org JSON-LD: `SoftwareApplication`/`WebApplication`(서비스) +
     `DataCatalog`(정본 카탈로그, `@id`=`.../catalog/current`). **판정·점수를 신설하지
     않는다** — 유형·출처·운영 주체 등 구조 사실만 기술한다(불변식 1 준수).
   - `#root` 내부에 정적 본문(정의·기능·한계·MCP 커넥터 URL·정본 문서 내비게이션)을
     둔다. React 마운트 시 교체되므로 화면 결과는 불변이다(Playwright 베이스라인
     통과로 확인). 문안은 About·Connect 화면과 같은 사실만 말한다.
   - 앱 내부 경로 링크는 `%BASE_URL%`을 쓴다 — 저장소 스택(base `/`)과 라이브
     프리픽스 배포가 다른 base로 빌드되므로, 하드코딩하면 한쪽에서 깨진다.

2. **정적 본문에 실시간 수치를 넣지 않는다.** 스냅샷·커버리지 수치는 월간으로 변하고,
   낡은 정적 수치는 "정직한 한계" 원칙의 반대(거짓말)가 된다. 정적 본문은 안정 사실만
   말하고 수치의 정본은 `/api/status`와 `llms.txt`로 가리킨다.

3. **`/llms.txt`는 정적 파일이 아니라 서버 라우트다.** 두 가지 근거:
   - 신선도 — 서버가 `/api/status`와 같은 원천에서 생성하므로 스냅샷 지연·커버리지
     분모가 배포와 함께 갱신된다(결정 2와 같은 원리).
   - 라우팅 — 라이브 배포에서 프로젝트 프리픽스 이하의 미지 경로는 전부 API로
     전달된다(catch-all). 웹 컨테이너의 정적 파일은 그 위치에서 서빙될 수 없다.
   - 등록 경로: 정본 `GET /projects/public-data-lens/llms.txt` + 루트 별칭
     `GET /llms.txt`(자체 호스팅 스택용 — 웹 nginx `location = /llms.txt`가 API로 전달,
     SPA 폴백이 index.html을 돌려주는 것을 차단).
   - 내용: 정의(블록쿼트) → 현재 상태(실시간 수치) → **판단 시 주의(계약 의미 —
     미수집≠품질문제, MISSING_FROM_SNAPSHOT≠폐기, BM25 상대값 등 CLAUDE.md 의미표의
     오독 방지 문안)** → MCP 연결 → 정본 URI → API·문서. 주 독자가 호스트 LLM이므로
     계약 의미 절이 핵심이다.

4. **SCHEMA_VERSION은 올리지 않는다.** `llms.txt`는 Tool 계약(부속명세)의 일부가 아닌
   안내 문서 표면이다. `gen_tool_spec.py` 재생성으로 tool-schemas 산출물이 바이트
   동일함을 확인했다(`generatedAt`만 변동 — 커밋하지 않음). 계약 스키마·enum·오류코드
   무변경이므로 minor 증가 요건에 해당하지 않는다.

## 결과

- JS 없는 소비자(크롤러·AI 에이전트·링크 미리보기)가 대표 페이지에서 정의·기능·
  한계·MCP 접점을 읽을 수 있다.
- `llms.txt`가 호스트 LLM에게 계약 의미(오독 방지)를 서비스 진입 시점에 전달한다 —
  P1(BM25 방향 오독)·P2(evals 오독 케이스) 작업의 선행 완충이 된다.
- 검증: 서버 pytest 전체 통과(라우트 테스트 추가 — `tests/test_dereference.py`),
  웹 build(라벨 가드)·vitest·Playwright core-desktop 통과, 빌드 산출물에서
  JSON-LD 파싱·meta·canonical 확인.

## 한계·후속

- 정적 본문은 홈 1페이지뿐이다 — 데이터셋 프로필 등 딥링크의 기계 판독(프리렌더·SSR)은
  범위 밖이며, 라이브 배포의 SPA 딥링크 라우팅 공백(프리픽스 이하 `/about` 등이 API
  404로 떨어짐)과 함께 별도 결정이 필요하다.
- `llms.txt`의 라이브 노출은 서버 배포에 묶인다 — 현행 배포는 v1.7.0이므로, ADR-011
  게이트 통과 후 v1.8.0 배포와 함께 나가거나 이 변경만 선별 배포해야 한다.
