# ADR-016: 스냅샷 수용 게이트 도입과 diff-v1.1 — 발행자 내보내기 변경을 실질 변경으로 오인하지 않는다

- 상태: 채택
- 날짜: 2026-08-21
- 관련: ADR-004·006(additive 계약 절차), ADR-014(배포 트레인 동결)
- 번호 주의: ADR-012~015는 미머지 PR(#5~#8)이 점유한다. 본 ADR은 016으로 시작한다.

## 맥락

2026-07 회차 CSV를 2026-06 회차와 전수 대조하는 과정에서, **포털 메타데이터가 바뀐 것이
아니라 발행자의 내보내기 경로가 바뀐 것**을 파이프라인이 실질 변경으로 판정한다는 사실이
드러났다. 두 가지 원인이 겹쳤다.

**(1) API 유형 블록의 엑셀 왕복.** 목록유형 `API` 11,960행 전량의 `등록일`·`수정일`이
ISO 날짜 대신 엑셀 1900 날짜 체계의 일련번호로 기재됐다(`2012-12-06` → `41249`).
`FILE` 83,850행·`STD` 300행은 무오염이다. 같은 행에서 `파일데이터명`이 `''` → `'-'`로
바뀌고 `설명` 필드의 셀 내 줄바꿈이 보존되는 증상이 함께 나타나, 원인이 스프레드시트
경유 저장임을 가리킨다. 1899-12-30 원점으로 환산한 값은 2026-06 회차의 `등록일`과
**11,929건 전건 일치(불일치 0)** 했다.

**(2) 내보내기 전역의 줄바꿈 처리 변경.** `설명` 필드에 줄바꿈을 포함한 행이
2026-06에는 96,056행 중 **0건**, 2026-07에는 **5,941건**이다. 6월 회차는 줄바꿈을
제거했고 7월 회차는 보존한다. 원문 충실도로는 7월 방식이 낫다.

`compute_changes`가 원시 문자열을 비교하므로, 두 원인이 합쳐져 변경 판정이 이렇게 나온다.

| 비교 방식 | MODIFIED | 그중 표기 요동 |
|---|---:|---:|
| 원본 그대로 | 17,812 | — |
| 일련번호 환산 후 | 11,768 | 11,583 (날짜) |
| 환산 + 공백 둔감 비교 | **5,566** | 6,202 (줄바꿈) |

즉 **변경행의 약 69%가 발행자 측 내보내기 아티팩트**였다. `get_catalog_changes`가
"설명이 바뀐 데이터 6천여 건"을 보고하는데 실제로는 한 글자도 바뀌지 않은 것들이다.

부수적으로, 채움률만 보는 점검이 이런 사안에 무력하다는 것도 확인됐다. `파일데이터명`은
`API` 행이 `''`→`'-'`, `STD` 행이 `'-'`→`''`로 뒤바뀌어 **채움률이 12.2pp '개선'된 것으로
보였으나** `is_empty()` 기준으로는 변화가 없다(`EMPTY`에 `"-"`가 포함된다).

또한 2026-08 회차로 수집한 API 합성본을 같은 방법으로 검사한 결과 조회수가
**96,080행 전부 감소**(2026-07 대비)해, 파일명과 달리 실질 시점이 7월 중순 빈티지임이
드러났다. 카운터 단조성 검사 하나가 이 판정을 자동화한다.

## 결정

**1. `normalize-date-v1.0` 신설.** `등록일`·`수정일`·`차기 등록 예정일`에 대해 ISO
날짜는 그대로 두고, 30000~60000 범위의 5자리 정수는 1899-12-30 원점으로 환산한다.
둘 다 아니면 원본값을 유지한다(§8 원본값 추적). 범위 하한은 연도 4자리를 일련번호로
오인하지 않기 위한 것이다.

**2. 변환은 침묵하지 않는다.** `issue-detect-v1.0`에 `EXCEL_SERIAL_DATE_ARTIFACT`(환산함)와
`UNPARSEABLE_DATE_FORMAT`(해석 불가)을 추가한다. 조용히 고치면 재발 시 아무도 모른다.
2026-07 회차에서는 23,920건이 관찰된다. `_collapse_systemic_issues`의 50% 임계 미달
(12.4%)이므로 레코드 단위로 남는다 — 의도한 동작이다.

**3. `diff-v1.1` 신설** (`diff-v1.0` supersede). 두 가지를 바꾼다.
- 감지 대상의 확장자를 `format_raw` → `formats`로 교체. `normalize_formats`가 대문자
  토큰 목록으로 환산하므로 `csv`↔`CSV` 표기 요동을 흡수한다(99건 → 47건).
- `title`·`org_name`·`theme_raw`·`license_raw`·`description`은 공백을 무시하고 비교한다.
  **저장값은 원문을 그대로 유지하고 비교 시점에만 정규화한다.**

**4. `license_raw`는 `license_code`로 바꾸지 않는다.** `LICENSE_MAP`의 키가 포털 실제
어휘(`"공공저작물 : 출처표시 (제 1유형)"`)를 담지 못해 2026-06·07 회차 모두 15,000여 건이
`OTHER`로 뭉개진다. 파생값을 추적하면 제1유형→제4유형 같은 **실제 라이선스 변경이
보이지 않는다.** 맵 정비를 선행 과제로 남기고, 그때 재검토한다.

**5. 스냅샷 수용 게이트 도입** (`scripts/verify_snapshot.py`). 빌드 전에 실행하며 차단
항목이 있으면 종료코드 1로 빌드를 막는다.

| 검사 | 차단 조건 | 이번에 잡은 것 |
|---|---|---|
| 헤더 구조 | 계약 36컬럼 누락 | — |
| 목록키 중복 | 1종 이상 | `record_id` 형태 변화 함정(잠재) |
| 날짜 형식 | ISO 위반 1건 이상 | 2026-07 일련번호 23,920건 |
| 카운터 단조성 | 감소 1건 이상 | 2026-08 합성본 빈티지 역행 |
| 채움률 델타 | −5pp 이상 하락 | 2026-08 합성본 6컬럼 소실 |
| 어휘 집합 델타 | 기존 어휘의 과반 소멸 | 2026-08 합성본 라이선스 재코딩 |
| 값 회귀 | 유지키의 1% 초과 셀 소실 | 위와 동일 |

채움률은 반드시 `is_empty()` 정규화 후 값으로 센다(`파일데이터명` 함정).
게이트는 `diff` 상태 분포도 미리 계산해 빌드 결과와 대조할 기대치를 남긴다.

## 계약 영향

**`SCHEMA_VERSION`은 올리지 않는다.** 규칙 id는 JSON Schema에 열거되어 있지 않고
(`tool-schemas-v1.8.0.json`에 `diff-v1` 문자열 0건, 규칙 id를 enum으로 고정한 위치
없음) 응답 봉투의 `rules` 배열 값으로만 노출된다. 규칙 id는 버전이 붙은 판정 근거이며
그 값이 바뀌는 것은 설계된 동작이다(불변식 5 — 프론트엔드는 문자열 패턴으로 계약 의미를
추론하지 않는다). 따라서 스키마 재생성 결과가 동일하며, 미머지 PR #5~#8과 같은
`SCHEMA_VERSION`을 두고 충돌하지 않는다.

`catalogMetadataCompleteness`·`region.evidence`·`license_code`는 이번 변경으로 값이
달라지지 않는다(2026-07 회차 실측: 완전성 0.8122, `EXPLICIT_SPATIAL` 3,732 —
2026-06의 0.8121·3,721과 정상 델타).

## 기각한 대안

- **일련번호를 그대로 흘린다** — `jsonld.py`의 `issued`·`modified`가 컨텍스트에서
  `xsd:date`이므로 부적합 리터럴 23,920개가 발행된다. SHACL 셰이프에 날짜 제약이 없고
  AIRD `datePresence`는 NOT NULL만 보므로 빌드 게이트를 그대로 통과한다.
- **`diff-v1.0`의 의미만 바꾼다** — 규칙 id는 판정의 버전 기록이다. 이름을 유지하고
  판정을 바꾸는 것이 이 설계가 막으려는 바로 그 일이다.
- **발행자 수정을 기다린다** — 수정 요청은 보냈으나(다른 이용자에게도 같은 영향) 우리
  진행을 그 일정에 묶지 않는다. 환산 정확도 100%가 검증됐으므로 자체 복원이 가능하다.

## 후속

- `LICENSE_MAP` 정비 → 그 후 `diff` 추적 대상을 `license_code`로 재검토
- SHACL 셰이프에 `dct:issued`·`dct:modified`의 `xsd:date` 제약 추가 — 이 유형은
  발행 전에 빌드 게이트에서 걸려야 했다
- `check-labels.mjs`의 명세 파일 선택이 문자열 sort다. v1.10.0이 되면 v1.9.0보다 앞으로
  정렬되어 구버전을 집는다(본 ADR은 버전을 올리지 않으므로 해당 없음)
