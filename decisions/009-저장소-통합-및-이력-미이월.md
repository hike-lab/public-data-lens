# 009. 저장소 통합 및 개발 이력 미이월

- 상태: 채택
- 일자: 2026-08-04
- 관련: `010-프로젝트-경계-및-자산-흐름.md`

## 맥락

공공데이터 렌즈는 두 저장소로 운영되어 왔다.

| 저장소 | 역할 |
| --- | --- |
| `haklaekim/public-data-lens` | 개인 계정, 메인 개발, 전체 커밋 이력 보유 |
| `hike-lab/public-data-lens` | 조직 계정, 공개용 릴리스 스냅샷 (스쿼시 커밋 1개) |

2원 운영의 비용이 실측되었다. 두 저장소의 README가 표현 차이가 아닌 **내용 차이**로 어긋난 상태가 확인되었다. 어느 쪽도 다른 쪽의 상위집합이 아니었다.

| 항목 | 개발 저장소 | 공개 저장소 |
| --- | --- | --- |
| AIRD 실증 포지셔닝 | 있음 | 없음 |
| 공정 사용 수치 (2 req/s) | 있음 | 없음 |
| 벌크 파일 안내 | 있음 | 없음 |
| ChatGPT 등록 절차 | 없음 | 있음 |
| 문서 표 | 6종 | 5종 |

동시에 `evals/`, `glossary/`, `decisions/` 신규 자산의 배치를 결정해야 하는 시점이 되었다. 2원 구조를 유지하면 자산마다 소유 저장소와 이월 여부를 개별 판단해야 하고, 이월 규칙이 사람 기억에 남는다.

## 결정

1. **`hike-lab/public-data-lens`를 유일한 공식 저장소로 한다.** 개발과 공개를 이 저장소에서 함께 수행한다.
2. **`haklaekim/public-data-lens`의 개발 이력을 이월하지 않는다.** 첫 공개 배포 시점을 관리 기준점으로 삼는다.
3. **`haklaekim/public-data-lens`는 삭제하지 않고 아카이브(읽기 전용)한다.** README를 공식 저장소로 안내하는 한 줄로 교체한다.
4. **이력을 대체하는 판단 기록은 `decisions/`가 담당한다.** 설계 판단이 커밋 메시지에만 존재하는 상태를 허용하지 않는다.
5. **이번 배포에 릴리스 태그(`v1.1.0-beta`)를 부여한다.** CITATION.cff의 `version`·`date-released`와 일치시킨다.
6. **공개 범위 정책**을 다음과 같이 확정한다.

| 경로 | 공개 | 근거 |
| --- | --- | --- |
| `evals/cases/**` | 공개 | 표준 시험 세트로 인용 가능한 자산 |
| `evals/results/**` | 미커밋(`.gitignore`) | 응답 원문이 누적됨. 사례집과 drift 리포트만 커밋 |
| `docs/사례_20선.md` | 공개 | 커넥터 미설치자가 보는 유일한 증거물 |
| `glossary/**` | 공개 | 표준 문안 원료이자 대외 인용 대상 |
| `decisions/**` | 공개 | 아래 영향 절 참조 |
| 원본 CSV·카탈로그 DB | 미포함 | 기존 정책 유지 |

## 기각한 대안과 이유

### A. 개발/공개 저장소 2원 운영 유지 + README 단일 정본 생성 스크립트

정본 하나를 두고 링크 치환·섹션 제거로 공개본을 생성하는 방식을 검토했다.

기각 이유: README가 이미 어긋난 상태를 복구하는 비용이 저장소 통합 비용보다 크다. 생성 스크립트는 README 하나만 해결하며, `evals`·`glossary`·`decisions`의 이월 규칙은 여전히 개별 판단으로 남는다. 2원 구조의 근본 문제는 파일 동기화가 아니라 **자산마다 소유권을 판단해야 한다는 점**이다.

### B. 개발 이력 이월 후 통합

이력 소실은 일반적으로 실질 손해다. 특히 "이 판정 규칙이 언제 왜 바뀌었나"의 시간 순서 증빙이 사라진다.

기각 이유: 이 프로젝트에서는 해당 정보가 **설계서 v1.0 확정판·부속명세 v1.0·매핑표 v1.0에 동결되어 문서로 존재**한다. 커밋 이력이 담을 고유 정보는 동결 이전의 시행착오뿐이며, 첫 공개 배포 시점에 정리해 버려도 되는 종류다. 단 이 판단은 **이후에는 성립하지 않는다** — 결정 4항(ADR 의무화)이 이 대안을 기각한 대가다.

### C. 컨시어지를 `haklaekim/public-data-lens`에서 계속 개발

기각 이유: 같은 이름의 저장소가 서로 다른 제품을 가리키게 된다. 인용·제안서에서 시점에 따라 다른 것을 지목하고, 렌즈 README의 개발 이력 링크가 컨시어지를 가리키게 된다. 상세는 ADR 002.

### D. `decisions/`를 비공개로 유지

ADR은 기각한 대안과 내부 판단 근거를 담으므로 비공개가 자연스러워 보인다.

기각 이유: 표준 제정 맥락에서 판단 근거의 공개는 신뢰 자산이다. 다만 부작용을 인지한다 — 공개를 전제하면 대외 표현을 고르게 되어 ADR의 가치인 솔직함이 줄어든다. 이를 아래 영향 절의 완충 장치로 관리한다.

## 영향

- 통합 시점에 README의 `개발 이력: haklaekim/public-data-lens` 항목을 제거해야 한다. CITATION.cff의 저장소 URL도 함께 점검한다.
- `evals` 작업지시서의 "개발 저장소 / 공개 저장소" 구분 문구는 단일 저장소 기준으로 개정해야 한다.
- **ADR 작성이 선택이 아니라 의무가 된다.** 커밋 이력을 버린 대가이므로, 설계 판단이 대화나 커밋 메시지에만 남는 상태를 허용하지 않는다.
- `decisions/` 공개에 따른 완충으로, 대외 공개가 부적절한 판단(계약 협상, 인사, 미공개 사업 계획)은 `decisions/`에 넣지 않고 별도 비공개 경로에 둔다. 판단 기준: 기술·설계 판단은 공개, 사업·계약 판단은 비공개.
- 아카이브된 저장소를 인용한 기존 URL은 404가 되지 않으나 갱신되지 않는다. 대외 문서에서 발견 시 공식 저장소로 교체한다.
- 릴리스 태그가 ADR 002의 시점 증빙 역할을 겸한다.
