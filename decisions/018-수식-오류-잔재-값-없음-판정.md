# ADR-018: 엑셀 수식 오류 잔재를 '값 없음'으로 판정한다 — normalize-empty-v1.0

- 상태: 채택
- 날짜: 2026-08-24
- 관련: ADR-016(스냅샷 수용 게이트·diff-v1.1·normalize-date-v1.0)
- 계기: 2026-07 회차 수정본(2026-08-24 수령)에서 발견

## 맥락

ADR-016에서 요청한 2026-07 회차 날짜 수정본이 도착했다. **P0는 정확히 해소됐다** —
날짜 시리얼 23,920건이 전부 ISO로 복원되고, 환산값이 우리 `normalize-date-v1.0` 계산과
**11,960/11,960(100.00%) 일치**했다. 등록일은 2026-06 회차와 11,929/11,929 일치한다.
1899-12-30 원점 가설의 독립 검증이다.

또한 확인 요청에 대한 답이 행동으로 왔다 — `설명` 필드의 줄바꿈 보유행이 5,961 → **0**으로,
2026-06과 같은 처리로 돌아갔다. **줄바꿈 제거가 발행자의 정책이다.** 회차별 추이는
`0 → 5,961 → 0`이며, 이 흔들림이 `diff-v1.1`의 공백 둔감 비교를 정당화한다.

**그런데 수정 과정에서 새 손실이 생겼다.** 3단계 변천을 재구성했다.

```
2026-06        '- 한국법제연구원에서 발간하고 있는 연속간행물중 법연, 최신외국법제정보…'   원문
2026-07 초판    '#NAME?'                                        엑셀이 '-' 시작 셀을 수식으로 해석
2026-07 수정판  'ME?'                                           수정 스크립트가 '#NA' 3자 추가 절단
```

손실 74건의 2026-06 원문 첫 글자가 **74/74 전부 `-`**다. 날짜 시리얼과 **동일한 원인**
(엑셀 왕복)인데 날짜만 고쳐지고 이건 남았다. 2026-06 회차에는 엑셀 오류값 흔적이 0건이므로
2026-07에 새로 생긴 것이 확정된다.

| 컬럼 | `ME?` | 완전성 평가 대상 |
|---|---:|---|
| 설명 | 33 | ○ |
| 기타 유의사항 | 19 | × |
| 데이터 한계 | 8 | ○ |
| 보유근거 | 7 | × |
| 수집방법 | 7 | × |
| 합계 | **74** | 41건이 점수에 영향 |

2026-06 원문 **11,769자가 3자로 대체됐다.** 복구 불가이며 발행자만 복원할 수 있다.
전수 검사 결과 다른 오류값(`#VALUE!`·`#REF!` 등)과 다른 선행문자(`=`·`+`·`@`)는 0건이다.

## 결정

**1. `normalize-empty-v1.0` 신설.** `is_empty()`가 미기재 마커(`""`·`-`·`null`·`없음`)에
더해 엑셀 수식 오류 잔재를 '사용 불가'로 판정한다. 표준 오류값 9종과 **실측된 절단 형태
`ME?`만** 포함한다 — 다른 절단 오프셋은 추측하지 않는다(미확인 형태는 수용 게이트의
'원문 급감' 검사가 그물 역할을 한다).

근거: **`ME?`를 데이터 설명으로 서빙하는 것보다 값 없음이 정직하다.** `#NAME?`는 사람·기계
모두 '엑셀 오류'로 식별할 수 있지만 `ME?`는 정체불명의 3자 문자열이고, `설명` 33건은
검색 색인(FTS)에도 들어간다. 원본값은 `source_json`에 보존된다(§8 원본값 추적).

**2. 값 없음 판정과 파괴된 값을 구별해 관찰한다.** `issue-detect`에
`EXCEL_FORMULA_ERROR_ARTIFACT`를 추가한다. 미기재와 파괴는 **판정이 같고 원인이 다르다** —
전자는 기관이 안 쓴 것이고 후자는 내보내기가 지운 것이다. 이 구별이 사라지면 발행자에게
무엇을 요청해야 하는지 알 수 없게 된다.

**3. `issue-detect-v1.1`로 버전을 올린다.** v1.0의 정의가 탐지 유형을 열거하므로 유형 추가는
정의 변경이다. ADR-016에서 `EXCEL_SERIAL_DATE_ARTIFACT`·`UNPARSEABLE_DATE_FORMAT`을
추가할 때 정의를 갱신하지 않은 누락도 함께 바로잡는다.

**4. `catalog-completeness-{file,api,std}-v1.1`로 버전을 올린다.** v1.0 정의의
"값이 없거나 '-'이면 미기재"가 바로 이번에 바뀐 판정 기준이다. 새 정의는 기준을
`normalize-empty-v1.0`에 위임한다. 영향은 41건(설명 33·데이터 한계 8)으로 평균 점수
변화는 무시할 수준이지만, **어떤 기준으로 산출된 점수인지 소비자가 알 수 있어야 한다.**
규칙 id는 판정을 감사 가능하게 만드는 장치이며, 쓰지 않으면 의미가 없다.

**5. 수용 게이트에 두 검사를 추가한다.** 이번 손상은 기존 게이트를 통과했다 — 셀이 비지
않아 '값 회귀'에 안 걸리고(값 있음 → 값 있음), 74건은 1% 임계 미달이고, 채움률 변화도 없다.

- **수식 오류 잔재** (WARN) — 서술형 10컬럼에서 전체 셀이 오류값과 정확히 일치하는 경우.
  차단하지 않는다: `normalize-empty-v1.0`이 결정론적으로 처리하고 관찰이 남으므로 74건이
  96,110행 빌드를 막을 이유가 없다. 대신 발행자 복원 요청 대상임을 문안에 명시한다.
- **원문 급감** (WARN) — 값이 남아 있는데 이전 회차 대비 20% 이하로 줄고 30자 이상 소실된
  셀. **빈값과 알려진 오류값은 제외한다** — 각각 '값 회귀'와 '수식 오류' 검사가 담당하며,
  같은 셀을 이중 보고하지 않는다. 이 검사에 남는 것은 정상 재작성과 미확인 손상의 혼합이라
  차단하지 않고 사람이 표본을 본다.

정교화 전에는 이 검사가 116건을 잡았다(빈값 47 + 실제 갱신 3 + 수식 오류 66). 정교화 후
**3건**만 남고, 그 3건은 수동 확인 결과 전부 정상 재작성이었다(예: `인천광역시 중구` →
`영종구` 행정구역 개편에 따른 설명 재작성).

## 계약 영향

`SCHEMA_VERSION`은 올리지 않는다. 규칙 id는 JSON Schema에 열거되어 있지 않고 응답 봉투의
`rules` 배열 값으로만 노출된다. `description`·`data_limits`가 41건에서 `null`이 되는 것은
필드 타입 변경이 아니며(이미 nullable), 계약 의미상 '미기재'다.

## 기각한 대안

- **그대로 적재** — `ME?`가 데이터 설명으로 서빙된다. `ME?`를 설명으로 읽는 사용자·호스트
  LLM이 생긴다.
- **2026-06 값으로 복원** — 마지막 정상값이지만, "2026-07 값이 틀렸으니 2026-06을 쓴다"는
  판단을 우리가 내리는 것이다. 날짜 환산은 **가역적 인코딩 복원**(41249 ↔ 2012-12-06,
  정보 손실 없음)이고 이것은 **소실된 원문의 대체**다. 성질이 다르다. 스냅샷은 그 시점의
  관찰이어야 하며, 다른 시점의 값을 몰래 채우면 스냅샷이 아니다.
- **수식 오류를 차단 사유로** — 74건이 전체 빌드를 막는 것은 비례하지 않는다. 결정론적으로
  처리 가능한 것은 차단이 아니라 처리 + 관찰의 대상이다.
- **절단 형태를 넓게 추측**(`NAME?`·`AME?` 등 포함) — 관측하지 않은 형태를 규칙에 넣으면
  정상 값을 삼킬 위험이 있다. 미확인 형태는 '원문 급감' 검사가 사람에게 넘긴다.
