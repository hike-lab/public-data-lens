# ADR-004: 계약 v1.5.0 — additive 확장 6종

- 상태: 채택 (STEP 8)
- 날짜: 2026-08-04

## 맥락

프론트엔드가 서버 책임을 복제하던 잔재(질의 해석 별칭 사전, 정렬 방식 문자열 추론,
경고 문자열 접두 결합, 스냅샷 지연 계산)를 걷어내려면 계약이 그 사실을 직접 말해야
한다. 가이드 §12의 additive 요청 목록을 구현했다. required 제거·타입 변경·오류코드
제거 없음 — minor(1.4.0 → 1.5.0).

## 변경 내역

1. **POST /api/plan** — `plan.py build_plan()`의 REST 노출(MCP `build_data_plan`과
   동일 조립기, 새 판정 없음). 웹 상세의 '활용 초안' 렌즈가 소비한다.
   렌즈 절대 규칙: DRAFT·NOT_ASSESSED·CANDIDATE_ONLY 상시 노출, fitSignals 4개
   개별 표시(종합 점수 금지), '추천' 명명 금지.
2. **`/api/search` `interpret=true`(옵트인) → `data.interpretedFilters[]`**
   `{field,value,sourceToken,ruleId}` — 검색어 토큰의 결정론 해석
   (**query-interpret-v1.0**, 레지스트리 등재·22종). 축당 최초 1토큰, 명시 필터
   우선. 프론트의 interpretQuery()와 별칭 사전 4종을 제거했고, 골든 케이스는
   `apps/server/evals/query_interpret_cases.json` + 테스트로 고정.
   MCP `search_datasets`에도 같은 옵트인 파라미터 추가.
3. **`notices[]{code,severity,text}`** — 모든 응답 봉투에 warnings[]의 구조화
   미러(warnings 유지). 상시 고지 = severity info(DISCLAIMER·GENAI_DISCLAIMER).
   WarningPanel은 notices가 있으면 severity로 분기(문자열 접두 결합 제거),
   구버전 응답은 접두 폴백.
4. **`ranking.direction`("desc") + `ranking.basis`("relevance"|"modified_date")**
   — 정렬 방식 문자열 패턴 추론 제거.
5. **`/api/status` `snapshotLagDays`** — 스냅샷 기준월 시작~배포 시각(일).
   홈 Coverage 블록은 서버 값을 우선, 구버전 응답만 폴백 계산.
6. **`/api/resources/eval`** — golden/eval_report.json 읽기 전용 노출.
   홈 Open Infrastructure에 P@10·R@10·nDCG@10 표기, humanReviewed=false를
   '자동 생성 골든셋(인간 검토 전)'으로 반드시 병기.

미구현(후속): `/api/stats?axis=regionEvidence`, `/api/changes.baseUnavailableReason`,
`summaryItem.evidenceLevel` — §12 목록의 잔여분, 전부 additive라 언제든 minor로 추가 가능.

## 동반 절차

`scripts/gen_tool_spec.py` 재생성(tool-schemas-v1.5.0.json, 라이브 검증 통과),
`SCHEMA_VERSION`/`SPEC_VERSION` 1.5.0, 스펙 경로는 버전 상수에서 도출(하드코딩 제거),
`test_contract_spec.py`·수용 테스트 갱신(봉투에 notices 포함). 서버 pytest 130 통과.
